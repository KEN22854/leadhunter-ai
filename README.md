# LEADHUNTER AI — CRM, поиск лидов и спроса, AI Message Studio

Рабочее пространство менеджера по продажам: **поиск предприятий по городу и категории** (OpenStreetMap) с автоматическим сбором опубликованных email и **аудитом сайта «что улучшить»**, **референсы** (AI-концепция улучшений + PDF + HTML-прототип), **кампании** с автоматической отправкой писем после одобрения, профиль лида, контакты с происхождением и статусами проверки, объяснимый Lead Score, AI-анализ, генерация персональных сообщений (3 варианта), редактор с версиями, AI Copilot, центр коммуникаций с ручным подтверждением каждой отправки, коммерческие предложения с экспортом PDF/DOCX, задачи и хронология.

Стек: Next.js 15 (App Router) · React 19 · TypeScript · Prisma 6 + SQLite · Tailwind CSS · Framer Motion · Anthropic SDK (Claude) · Vitest.

## Быстрый старт

```bash
npm install
npm install-scripts approve @prisma/client @prisma/engines esbuild prisma   # npm 11+: разрешить скачивание движка Prisma
cp .env.example .env        # затем впишите ANTHROPIC_API_KEY (необязательно)
npm run setup               # миграции + AUTH_SECRET + тестовый пользователь и демо-лиды
npm run dev                 # http://localhost:3210
```

Вход — `SEED_USER_EMAIL` / `SEED_USER_PASSWORD` из `.env` (тестовый локальный пользователь). Демо-лиды вымышлены и используют зарезервированные домены `*.example`.

Пользователи: `NEW_USER_PASSWORD="…" npm run user:create -- <логин> "<Имя>" admin` — вход по короткому логину или email. Администратор настраивает почту (SMTP/IMAP), Telegram, WhatsApp и ключи API источников в **Настройки → Подключения**: секреты шифруются в БД (AES-256-GCM, ключ из `AUTH_SECRET`), применяются без перезапуска и важнее значений из `.env`. Если сменить `AUTH_SECRET`, сохранённые секреты придётся ввести заново.

Подключение соцсетей пошагово — [docs/SOCIAL_SETUP.md](docs/SOCIAL_SETUP.md); проверка каждого источника — кнопки «Проверить» в «Настройки → Подключения» и «Спрос → Источники».

Проверки: `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`.

## Ответы в Threads через официальный API

**Настройка:**
1. На developers.facebook.com создайте приложение со сценарием «Access the Threads API».
2. Добавьте разрешения: `threads_basic`, `threads_keyword_search`, `threads_content_publish`, `threads_manage_replies`.
3. Добавьте свой профиль Threads тестировщиком.
4. Получите долгоживущий токен (60 дней).
5. Пройдите App Review для `threads_keyword_search`: без него поиск идёт только по вашим постам.
6. Вставьте токен в **Настройки → Подключения → Источники «Спроса»: соцсети**. Там же задаются дневной лимит ответов (по умолчанию 20) и пауза между ответами (по умолчанию 5 минут).

**Работа:**
1. Кампания «Спроса» с источником Threads и расписанием «Ежедневно» сама ищет посты.
2. В **Исходящих** кнопка «Подготовить ответы» пишет короткий ответ каждому горячему или тёплому лиду: AI, а если он недоступен — шаблон по фактам поста, до 500 символов.
3. Вы проверяете тексты, правите их и одобряете пачкой.
4. Фоновая задача `threads-replies` публикует одобренные ответы через API по одному: с паузой, в пределах дневного лимита приложения и квоты Meta (1000 ответов в сутки).
5. Каждую публикацию можно также отправить сразу, кнопкой из карточки лида.

**Защита от спама** (Meta считает спамом массовые одинаковые ответы незнакомым людям даже в пределах квоты):
- одному автору — только один ответ;
- перед каждой публикацией заново проверяются Do Not Contact и отказы;
- без вашего одобрения ничего не публикуется;
- личных сообщений в Threads API нет.

После публикации создаётся карточка в CRM с задачей «Проверить ответ» через 3 дня.

## Поиск лидов: охват, лимиты, рейтинг, фильтры

- **Охват.**
  - Город и страна необязательны: без города поиск идёт по всей стране, без обоих — по всему миру.
  - Город ищется через Overpass, страна и мир — через Nominatim, страницами по 40 мест.
  - Мир обходится по странам, крупные рынки первыми.
- **Лимит.** Поле «Максимум» необязательно. Без него поиск идёт партиями, пока источник не исчерпан, пока вы его не остановите или пока не кончится бюджет честного использования публичного Nominatim (60 запросов на поиск). Со своим `NOMINATIM_URL` бюджет — 1000 запросов, предел — 5000 результатов. Временные ошибки (503, сеть) повторяются, после 4 сбоев подряд поиск приостанавливается, найденное сохраняется.
- **Рейтинг выдачи** — сортировка по умолчанию, 0–100:
  - возможность написать — email › сайт › телефон › соцсети;
  - популярность — бренд/сеть, Wikidata, полнота карточки;
  - известность — importance Nominatim;
  - бонус «есть что улучшить» после аудита.

  В OSM нет отзывов и звёзд, поэтому настоящий рейтинг площадок не используется. Проверка сайтов идёт в порядке рейтинга.
- **Выдача** — страницами по 25/50/100. Фильтры:
  - контакт: email, сайт, телефон, любой, без сайта;
  - «что улучшить»;
  - статус проверки сайта;
  - есть ли в CRM;
  - минимальный рейтинг;
  - страна;
  - текст.

  Сортировки: рейтинг, худшие или лучшие сайты, название, новые. Лиды «Спроса» тоже идут страницами, а лимит результатов кампании необязателен.
- **Дизайн.** Монохромный (чёрный/белый) с полупрозрачными «стеклянными» панелями, светлая тема — инверсия.

## Основной сценарий

1. **Поиск лидов** → категория (например, «Кофейни и кафе»), город, страна → «Найти». Заведения берутся из OpenStreetMap; в фоне каждый сайт проверяется: ищутся опубликованные email (mailto, текст, «[at]», JSON-LD — адреса не угадываются) и выполняется аудит (HTTPS, мобильная версия, скорость, вес, SEO-разметка, Open Graph, контакты, карта, соцсети, для общепита — меню и бронь, для услуг — онлайн-запись и цены). Сети с одним сайтом схлопываются, ссылка на VK/Telegram вместо сайта = «нет собственного сайта».
2. Отметить нужные → **«В CRM»**: создаются клиенты с контактами, источниками (OSM + сайт) и аудитом.
3. Карточка → вкладка **«Референс»**: «Сгенерировать референс» — AI пишет концепцию по фактам аудита, письмо от имени исполнителя (профиль в «Настройках») и, по кнопке, HTML-прототип главной. PDF с концепцией скачивается и прикладывается к письму.
4. **Кампания** (из поиска или вручную): письма для всех лидов, недостающие референсы генерируются кнопкой. После проверки — «Одобрить и запустить»: письма уходят **автоматически** по одному с паузой, в рабочие часы и с дневным лимитом. Перед каждым письмом заново проверяются список запрета, «Не связываться», основание и статус адреса.
5. Ответы приходят по IMAP: ответ → задача «Ответить» и статус «Переговоры», «отпишитесь» → список запрета, отказ доставки → адрес недействителен. Остальным письма этому клиенту не уходят.
6. Клиент согласился → **«Создать рабочий проект»**: папка `workspace/<клиент>/` с brief.md, concept.md, prototype.html и CLAUDE.md. Откройте её командой `claude` — и продолжайте делать сайт в отдельной сессии Claude Code с полным контекстом.

## Модуль 2: «Спрос в соцсетях» (Social Lead Generation & AI Outreach)

Раздел **«Спрос в соцсетях»** (`/signals`) ищет людей и компании, которые **публично** ищут исполнителя, просят рекомендации, запускают проект или выставили заказ на бирже.

**Сценарий:** «Новая кампания» → услуга, страна/город, языки, источники, ключевые и стоп-слова, тип бизнеса и заказа, период, максимум результатов, минимальный Lead Score, расписание (однократно / ежедневно / еженедельно) → результаты по каждому источнику: получено, отфильтровано и почему, сохранено, дубликаты, ошибки. Дальше карточка лида:
- все публикации автора;
- намерение с объяснением;
- Lead Score по 7 факторам;
- ключи дедупликации;
- журнал оснований;
- три варианта обращения с редактором.

Отправка — только через способ, допустимый для площадки, и только с вашим подтверждением.

**Источники** — отдельный адаптер на каждую площадку (`src/lib/signals/adapters.ts`, каталог — `catalog.ts`, 35 записей):

| Доступ | Площадки |
|---|---|
| Открытые данные, без ключа (проверены вживую 14.11.2026) | FL.ru (RSS), Kwork (первая страница биржи, разрешена robots.txt), Freelancer.com (официальный API), Dribbble (RSS вакансий), Product Hunt (Atom), VC.ru (RSS), Хабр (RSS поиска), Hacker News (Algolia API), свои RSS-ленты, публичные Telegram-каналы (`t.me/s/…`, из этой сети t.me недоступен) |
| Официальный API, нужен ключ в `.env` (реализованы, без ключей не проверены) | Reddit (OAuth app-only), VK (`newsfeed.search`), X (recent search), Threads (keyword search), Instagram (хэштеги), Discord (бот в ваших серверах), Google Custom Search, Yandex Search API, Google Places, Яндекс Карты (поиск организаций), 2ГИС, Crunchbase |
| Ручной режим: разрешённого API нет | LinkedIn, Facebook, Upwork, Fiverr, PeoplePerHour, Freelance.ru, Behance, Pinterest, Clutch, Indie Hackers, Хабр Фриланс (robots.txt запрещает). Система строит ссылки поиска по фразам кампании, а найденную публикацию вы добавляете через «Добавить вручную». Дальше всё идёт по общему пути: анализ, скоринг, дедупликация. |
| API закрыт | Bing (Microsoft отключила Bing Search API 11.08.2025) |

**Поиск и фильтрация** (`classify.ts`, `lexicon.ts`):
- словари услуг на 5 языках (ru/en/de/fr/es) с синонимами и словоформами;
- шаблоны намерений и признаки самопрезентации исполнителя;
- признаки конкретики (бюджет, сроки, ТЗ);
- новый язык добавляется записью в словари.

Совпадение в заголовке весит больше. Чужая роль в заголовке (продажи, ввод данных, перевод…) штрафуется.

Намерения: конкретный заказ, ищет исполнителя, постоянный подрядчик, рекомендации, партнёр, запуск, интерес, нет интереса. По ним лиды делятся на горячие, тёплые и потенциальные. Если AI подключён, он уточняет намерение для лучших 45 кандидатов. Если AI недоступен, работают правила, а запуск честно пишет об этом.

**Lead Score** (`scoring.ts`) — 7 факторов с объяснением, в сумме 100:
- актуальность запроса — 25;
- соответствие услуге — 20;
- конкретный проект — 15;
- свежесть — 15;
- качество источника — 10;
- достоверность контакта — 10;
- соответствие ЦА — 5.

Без коммерческого намерения итог не выше 25. Повторные запросы того же автора добавляют до +9.

**Дедупликация** (`identity.ts`, `store.ts`) по профилю, домену, email, телефону и ID в источнике. Новая публикация, совпавшая с несколькими лидами, объединяет их в одну карточку и пишет запись в журнал.

**AI Personal Outreach** — три варианта: дружелюбный, деловой, краткий. AI получает текст публикации, профиль автора, ваш профиль и портфолио, язык и историю обращений. Есть шаблон без AI, построенный только на фактах публикации и профиля. В редакторе: сохранение с версиями, «дружелюбнее», «деловее», «короче», перевод, повторная генерация.

**Outreach Channel Manager** (`outreach.ts`) поддерживает три режима:
- **официальная отправка** — только email, опубликованный автором; уходит через SMTP центра коммуникаций CRM;
- **открытие исходного диалога** — текст копируется, вы отправляете сами;
- **отклик механизмом площадки** — для бирж.

Обязательные проверки перед отправкой:
- контакт;
- Do Not Contact;
- отказ;
- повторное обращение без ответа;
- предпросмотр;
- подтверждение.

Статусы фиксируют только подтверждённые факты:
- `prepared` — подготовлено;
- `opened` — диалог открыт;
- `confirmed_sent` — вы подтвердили, что отправили;
- `sent` — SMTP принял письмо;
- `failed` / `cancelled`.

Подтверждённая отправка создаёт карточку в CRM: источник, контакты, основание «опубликованный запрос», follow-up через 3 дня, запись в хронологии. Положительный ответ переводит клиента в «Переговоры» и ставит задачу. Отказ вносит человека в Do Not Contact.

**Аналитика** (`/signals/analytics`):
- лиды по источникам, услугам и странам;
- горячие заказы;
- подготовленные сообщения и подтверждённые отправки;
- ответы, положительные ответы, отказы;
- конверсия;
- среднее время до первого контакта.

Подготовленное не считается отправленным. Прочтение не считается вовсе.

**Мониторинг**: задача `signals` в фоновом планировщике раз в минуту запускает кампании по расписанию. По каждому источнику действуют:
- минимальный интервал между запросами;
- дневной лимит;
- повтор временных ошибок (до 3 попыток);
- экспоненциальная пауза после сбоев;
- пауза по `Retry-After` при ответе 429.

401/403 — это стоп, а не повод обходить. Состояние источников видно на странице «Источники». Кнопка «Повторить источники с ошибками» перезапускает только сбойные.

**Безопасность и данные:**
- единый Do Not Contact с CRM, включая профили (`profile:host/path`);
- адреса из списка не собираются повторно и блокируются при любой отправке;
- журнал оснований обработки: сбор, объединение, обращение, передача в CRM, запрет, удаление;
- удаление данных лида с обезличиванием журнала и запретом повторного сбора;
- массовой рассылки и автоматизации личных сообщений нет.

Живая проверка без UI: `npm run signals:smoke -- website fl_ru,kwork,freelancer,hn,habr`.

## Необходимые ключи и доступы

- **Claude Code (подписка Claude)** — проще всего: выполните `claude` в терминале и войдите в аккаунт. Приложение вызывает `claude -p` в пустой папке со **всеми инструментами отключёнными** (модель только генерирует текст/JSON), без MCP и без сохранения сессий; не больше 2 вызовов одновременно. Расходуются лимиты подписки.
- **Anthropic API** — console.anthropic.com → API Keys. Оплата по токенам. Расход по обоим способам виден в «Настройках» (журнал `AIUsageLog`; для подписки — оценка по прайсу API).
- **OpenStreetMap** — ключ не нужен. Публичные Overpass бывают перегружены: приложение пробует несколько серверов, а при отказе всех ищет через Nominatim (меньше результатов, в поиске показывается предупреждение).
- **SMTP** — ящик/домен для деловой переписки с настроенными SPF/DKIM/DMARC.
- **Telegram** — бот у @BotFather. Бот может писать только тем, кто сам начал с ним диалог; входящие подтягиваются кнопкой «Синхронизировать Telegram» (`getUpdates`, сопоставление по username контакта).
- **WhatsApp** — аккаунт WhatsApp Business Platform (Meta), номер, постоянный токен и одобренный шаблон. Вне 24-часового окна отправляется только шаблон.
- **LinkedIn** — открытого API для личных сообщений нет; статус «Недоступно», текст копируется и отправка отмечается вручную.

```
    export/           КП → PDF (pdfmake, Roboto с кириллицей) и DOCX (docx)
    score.ts          объяснимый Lead Score (чистая функция)
    outreach.ts       подготовка → подтверждение → отправка, идемпотентность, входящие, отписка
    compliance.ts     suppression-list, «Не связываться», правовое основание, статус контакта
    webfetch.ts       загрузка публичных страниц: SSRF-защита, robots.txt, таймауты, лимит размера
prisma/               схема, миграции, сид
tests/                unit + интеграционные тесты API на отдельной БД
```

### Модель данных

`User`, `ExecutorProfile`, `Client`, `Contact`, `LeadSource`, `FieldProvenance` (происхождение полей и конфликты), `LeadAnalysis`, `LeadScore`, `AIMessage` + `AIMessageVersion`, `MessageTemplate`, `Conversation` + `ConversationMessage`, `Interaction` (timeline), `ClientTask`, `Deal`, `Proposal` + `ProposalVersion`, `ConsentRecord`, `SuppressionEntry`, `CopilotMessage`, `AIUsageLog`, `AuditLog`.

Миграции: `prisma/migrations/…_init`, `…_message_evidence`. Изменения схемы — только через `npm run db:migrate`.

### AI

- Все вызовы — только на сервере (`src/lib/ai/provider.ts`), ключ из окружения.
- Структурированные ответы по zod-схемам (structured outputs): анализ, 3 варианта сообщения с доказательствами персонализации, переписывание фрагмента, черновик КП, ответ на входящее. Copilot — свободный текст.
- Промпты версионируются (`analysis-v1`, `message-v1`, …); версия и модель сохраняются вместе с результатом.
- Внешние данные (сайты, входящие сообщения, инструкции пользователя) оборачиваются в теги и экранируются; системный промпт требует считать их данными, а не инструкциями. Значения email/телефонов в модель не передаются.
- Включены серверные fallbacks (`server-side-fallback-2026-07-01`, `fallbacks: "default"`): при отказе модели по политике запрос повторяется на резервной модели. Отказ, таймаут, rate limit и ошибки провайдера отображаются пользователю; введённые параметры и тексты сохраняются.
- SDK делает повторы с backoff (`maxRetries: 3`); дополнительно стоит лимит запросов на пользователя.

### Отправка сообщений

1. «Подготовить к отправке» → проверки (список запрета, «Не связываться», правовое основание, статус контакта) → статус «Ожидает подтверждения». К email автоматически добавляется строка об отказе от рассылки.
2. «Подтвердить и отправить» — отдельное явное действие с чек-боксом, `confirm: true` и ключом идемпотентности. Атомарный переход в «Отправляется» защищает от двойной отправки.
3. Ошибка канала → статус «Ошибка» с причиной, текст сохраняется, повтор после устранения.
4. Ответ «отписаться» во входящих автоматически добавляет контакт в список запрета.

Массовой и автоматической рассылки нет по замыслу.

## Известные ограничения и дальнейшие задачи

- **Сеть для AI**: Anthropic отклоняет запросы из неподдерживаемых регионов и некоторых сетей (HTTP 403). На этом компьютере прямой вызов из приложения получил 403 — приложение показывает это как «AI недоступен с этого подключения». Генерация проверена из другой сетевой среды той же машины.
- **Законность рассылки**: реклама по email без согласия ограничена (РФ — ст. 18 ФЗ «О рекламе», ЕС — ePrivacy/GDPR). Приложение пишет только на опубликованные деловые адреса, фиксирует основание с источником, добавляет отписку и List-Unsubscribe, соблюдает лимиты — но ответственность за содержание и страну получателя на отправителе.
- Доставляемость: для холодных писем нужен отдельный домен/ящик с SPF/DKIM/DMARC и прогревом; начинайте с 10–20 писем в день.
- Overpass/Nominatim — публичные бесплатные сервисы с лимитами; для регулярной работы поднимите свой инстанс.
- Входящие WhatsApp (webhook) не реализованы; Telegram — по кнопке. Вложения — только email.
- Rate limit и фоновый планировщик работают внутри одного процесса; для нескольких инстансов нужны Redis и внешняя очередь. Офсеты Telegram/IMAP хранятся в БД.
- Не обновлены мажорные версии Next 16 и Prisma 7 (`npm audit`: уязвимости в инструментах сборки — PostCSS внутри Next, deepmerge в Prisma CLI); переход требует отдельной миграции.
- UI-тестов (Playwright) нет — интерфейс проверен вручную.
- Оценка визуала сайта — только по тексту и структуре страниц, без скриншотов.
- Поиск дубликатов — по нормализованному значению контакта у клиентов того же пользователя.
- Нет ролей команды и назначения задач другим пользователям (поле `assigneeId` готово). Сделки (`Deal`) есть в схеме, но без UI.
- Локализация: подписи в `src/lib/domain.ts` и компонентах на русском; для других языков их нужно вынести в словари.
- SQLite подходит для локальной работы; для продакшна — PostgreSQL и шифрование диска/БД.
